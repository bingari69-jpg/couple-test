## 1. P0 — 게임이 실제로 망가져 있는 것

### 1.1 10초 맞추기: 시작하자마자 멈추면 무조건 이긴다 **[확인]**
`t/ten/index.html:187` `isLegacy = v => v >= 5000`

옛 링크 형식을 값 크기로 구분하는데, 지금 그 값은 오차다. 0.02초에 멈추면 오차 9980ms가 `errOf`에서 20ms로 뒤집히고, 화면에는 `label()`을 타서 "9.98초"로 표시된다. 부정이 보이지도 않는다. 반대로 4.9초에 정직하게 멈춘 사람은 4900으로 손해를 본다.

고치는 법: 링크에 이미 `v`와 `t` 배열이 있으므로 `isLegacy = p => !Array.isArray(p.t)`로 판정. 1초 미만 정지는 무효 처리. **S**

### 1.2 한글 타자: 모든 문장의 마지막 글자가 오타 처리 **[확인]**
`t/typing/index.html:359` `else if(state.typed.length >= t.length)`

한글은 한 음절에 최소 두 번을 누르는데, 조합 중 판정(`partialOf`)을 화면 표시에만 쓰고 진행 조건에는 안 쓴다. 마지막 글자의 초성만 눌러도 문장이 넘어가며 오타 1이 붙는다. 72문장 전부 해당. 동점 처리 기준이 오타 수라 승부에도 영향. **S**

### 1.3 지뢰찾기·15퍼즐: 아무것도 안 한 쪽이 이긴다 **[확인]**

## 2. P1 — 공정성과 약속

### 2.1 "한 번뿐" 약속이 코드로 지켜지지 않는다
`assets/duel-engine.js:199-237` 이미 푼 도전장 잠금은 끝까지 푼 뒤에만 기록된다. 중간에 새로고침하면 같은 시드를 처음부터 다시 받는다. 도전자 쪽은 잠금 자체가 없다. 시드 게임은 판을 외운 뒤 다시 푸는 게 가장 센 전략이 된다. 기록 대결 전 종에 해당. **M**

### 2.2 연타가 실력을 이긴다
| 게임 | 근거 | 수치 |
|---|---|---|
| 화살표 함정 | 오답 벌점이 0.4초 잠금뿐 | 막 연타 29.3개 vs 성실 33개 |
| 두더지 잡기 | 빈 구멍을 쳐도 손해 없음 | 난타만으로 23.1점, 칭호 "손이 빠르다" |

화살표는 기록을 정답에서 오답을 뺀 값으로 바꾸면 연타 기대값이 0이 된다. 두더지는 빈 구멍 감점이나 구멍별 쿨다운. **S**

### 2.3 "봉인"이라고 쓴 곳 중 셋은 잠금이 전혀 없다
- `t/crash/index.html:251` 8문항 답이 평문

나머지도 2~4회 반복이면 풀린다. 링크에 잠금 키와 값이 함께 실리기 때문이다. 정적 사이트에서 완전 차단은 불가능하니, 엿보기가 곧 점수가 되는 곳(결혼·취향·배달·MBTI·기억·넌센스)만 난독화하고 나머지는 문구를 사실에 맞게 낮추는 게 맞다. **M**

### 2.4 사다리·조편성의 공정성은 실제로 균등하다
6만 회와 20만 회 시뮬레이션으로 확인됐다. 다만 "만드는 사람도 미리 볼 수 없어"는 지킬 수 없는 약속이다. 링크를 열어 전체 결과를 본 뒤 다시 뽑으면 된다. 문구를 정직하게 고치는 편이 낫다. **S**

### 2.5 배달 텔레파시에 재도전 잠금이 없다
문항마다 정답을 바로 공개하는데 잠금이 없어 새로고침으로 만점을 만들 수 있다. 결과 링크의 점수도 평문이다. 가위바위보의 잠금 코드를 그대로 옮기면 된다. **S**

## 5. P2 — 구조 부채

게임이 늘수록 비용이 선형으로 커지는 것들.

1. **페이지가 곧 복붙 단위다.** 새 게임 하나에 DOM id 39개, 결과 화면 마크업 1.4KB, 시드 난수 함수를 손으로 옮긴다. 엔진은 누락을 검증하지 않아 하나만 빠져도 런타임 오류.
2. **캐시 버전이 수동이다.** `analytics.js` 한 줄을 고치면 HTML 45개를 손으로 바꿔야 한다. 현재 테스트는 "서로 다른 버전"만 잡고 "안 바꾼 것"은 통과시킨다. 내용 해시로 바꾸는 게 맞다.
3. **모든 페이지가 쓰지 않을 것을 받는다.** Supabase SDK와 익명 로그인, 실시간 연결이 첫 방문자에게도 열린다. 한글 폰트 두 벌(659KB)과 편지 폰트(최대 2.4MB)가 서브셋 없이 내려온다. 홈은 쓰지도 않는 IBM Plex Mono를 받는다.
4. **통계 숫자가 틀렸다.** "게임 완료"는 사실상 링크 생성 수다. `game_started`는 혼자놀기 레벨 버튼 클릭도 센다. 광고 노출은 홈 1회 방문에 6회 전송된다. `broken_link`는 허용 목록에 없어 서버에 도달하지 않는다.
5. **테스트가 공통 로더를 안 돈다.** app-config, help-guide, result-notify가 실제 게임 페이지 위에서 한 번도 실행되지 않는다. 지금까지 터진 장애(중복 버튼, 광고 소실, 버전 불일치)가 전부 이 빈칸에서 나왔다.

- "세상에서 가장 ~한" 틀이 100개 중 28개
- 4지선다 자체보다 오답 보기 품질이 원인. 앞서 별도 검토한 내용과 일치한다

### 6.4 원고 수준이 두 층으로 갈린다
싸우면 어떻게 끝날까의 유형 원고, 결혼 테스트의 대화 프롬프트, MBTI 16유형 한 줄 평, 타로의 민감 카드 처리는 충분히 좋다. 반면 마음동물 세 유형은 같은 템플릿 3회, 운세 18장은 같은 어미에 "작은"이 9회, 기억의 `lines.half`는 도달 불가능한 죽은 문구다.

### 6.5 사용법에 혼자놀기가 없다
안내 페이지는 여전히 "모든 놀이는 카톡 3단계"라고 말한다. 혼자놀기 13종의 레벨·별 규칙이 한 줄도 없다. 제한 시간이 있는 5종의 시간 표기도 빠졌다.

## 7. P1 — 단체방

세 가지 교착 경로가 있다. 전부 서버 함수 추가가 필요하다.

1. 방장이 탭을 닫으면 아무도 시작하거나 결과를 열 수 없다. 위임도 취소도 없다.
2. 링크만 눌러보고 나간 한 명 때문에 전원이 결과를 못 본다. 내보내기도 건너뛰기도 없다.
3. 익명 세션을 잃으면 같은 이름으로 재입장이 거부된다. 시작 후에는 재입장 자체가 막힌다.

그 밖에 실시간 연결이 끊겨도 표시가 없고, 결과가 나온 뒤에도 5초 폴링이 영구히 계속되며, 10초 모드 점수를 클라이언트가 보내 조작이 가능하다.

반대로 결과 확정이 정확히 한 번만 일어나는 것과 인원 상한이 DB에서 강제되는 것은 잘 돼 있다.

## 9. 권하는 실행 순서

**1단계 — 지금 사용자가 손해 보는 것 (반나절)**
10초 맞추기 판정, 한글 타자 조합 판정, 지뢰·15퍼즐 동점 기준, 끼워넣기 목록 등록, 탭 비행 문 겹침, 스네이크 먹이 동기화, 배달 주인 화면 버튼, 시험지 문제 추가 막힘.

**2단계 — 공정성 (하루)**
새로고침 재시도 잠금, 화살표·두더지 연타 대책, 배달 재도전 잠금, "봉인" 문구를 사실에 맞게 조정, 완료 코드 권한 검사.

**3단계 — 혼자놀기 레벨 재조정 (하루)**
12종 실측 후 goal/best 재설정, 잠금 완화, 별 중간 기준 표시.

**4단계 — 콘텐츠 (이틀)**
조사 16곳, 결과 라벨 경계, 넌센스 오답 보기, 사용법에 혼자놀기 추가.

**5단계 — 구조 (계속)**
캐시 버전 해시화, 공통 로더 테스트, 통계 이벤트 정정, 폰트 서브셋, 관리센터 순서 편집.
