# 알까기 배틀

- 페이지: `/t/alkkagi/`. 기본 컴퓨터전, `?mode=local`은 같은 화면에서 둘이, `?mode=online`은 카톡 초대 친구전이다. 기존 크림·코랄 UI와 로컬 주아 글꼴을 사용한다.
- 흑돌 5개·백돌 5개, 흑돌 선공. 내 돌 선택 → 판에서 방향 선택(또는 8방향 버튼) → 힘 10~100 조절 → 튕기기로 확정한다. 돌을 선택하는 것만으로 발사하지 않는다.
- 돌 중심이 판의 경계를 넘으면 탈락한다. 충돌과 마찰이 멈추면 다음 차례다. 내 돌도 떨어질 수 있다. 상대 돌을 모두 떨어뜨리면 승리, 양쪽이 동시에 모두 떨어지면 무승부. 120회 제한에서는 남은 돌이 많은 쪽이 이기고 같으면 무승부다.
- 컴퓨터는 가능한 내 돌·상대 돌·힘 조합을 직접 시뮬레이션해 상대 탈락, 내 돌 보존, 가장자리 위험을 비교한다. 상대 돌을 전부 떨어뜨리는 수가 우선이다.
- 클라이언트 물리는 `rules.js`, 서버 물리는 `supabase/migrations/20260914_alkkagi_rooms.sql`. 시간 간격 1/120초, 마찰 0.985, 최대 720단계, 반지름 0.035, 충돌 반발 계수 0.94(동일 질량 충격량 계수 0.97)를 공유한다. 최종 위치는 소수점 6자리로 정리한다.
- 온라인에서는 클라이언트가 돌 번호·각도·힘·판 버전만 보낸다. 서버가 참가자·차례·내 돌·범위를 검증하고, 행 잠금 안에서 충돌과 탈락을 계산한다. 최종 위치나 승패를 클라이언트로부터 받지 않는다. 화면은 서버가 돌려준 이전 판과 발사 정보로 움직임을 재생하고 서버의 최종 상태로 맞춘다.
- 온라인은 1.5초 간격 상태 확인, 같은 브라우저 익명 계정 재입장, 동시/중복 발사 방지, 양보하기, 두 사람 동의 후 재대결을 지원한다. 별도 세 번째 참가자는 들어갈 수 없다. 만료 24시간, 사용자당 방 생성 시간당 12회. 기존 단체방 접속 모듈을 재사용한다.
- **로컬 구현·검증 완료, 운영 SQL 미적용·미배포·미커밋 상태다.** 서버 관리 화면의 자동 조작이 브라우저 주소 확인 실패로 중단된 상태여서 운영 적용을 완료하지 못했다. 실제 카톡 초대는 신규 SQL 적용 후 앱을 배포해야 가능하다. 카카오 공유 코드는 실제 서비스 도메인에서만 초대 링크를 보낸다.

## 검사와 체험

- `node test/alkkagi.js`: 물리/규칙, 컴퓨터 수, 실제 SQL과 브라우저의 최종 위치/탈락/승패 일치, 차례·남의 돌·힘 범위·중복 발사·직접 테이블 접근·재대결·만료, 실제 페이지 선택과 확정.
- `node scripts/check-alkkagi.cjs`: 320/390/768/1024px 화면, 실제 애니메이션과 컴퓨터 응수, 독립 브라우저 2개 대전, 동일 좌표, 새로고침/접속 끊김 복구, 제3자 거절, 재대결, 홈 진입. 화면은 `output/alkkagi/`.
- `node scripts/alkkagi-preview.cjs`: 운영 데이터와 연결하지 않는 실제 SQL 기반 로컬 체험. `http://127.0.0.1:4188/t/alkkagi/?mode=online&player=0`에서 방을 만든 뒤, 같은 `#room=...`을 붙인 `?mode=online&player=1#room=...`을 다른 탭에서 열어 친구 역할로 입장한다. 서버 종료 시 체험 데이터는 사라진다. 이 체험 서버는 운영 앱에 배포하지 않는다.

서버 만료 데이터의 자동 삭제는 별도 보관 정책에 따라 추가해야 한다. 다른 브라우저/카톡 내 브라우저는 익명 계정이 다를 수 있으므로 재입장은 처음 사용한 브라우저에서 한다.
