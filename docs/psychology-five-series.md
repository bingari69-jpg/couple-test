## 호환성과 배포

- 기존 `/t/personality/`, `/t/mbti/`, `/t/seat/`, `/t/tarot/`, `/t/fortune/`, `/t/mind/fight/`, `/t/marriage/` 페이지·엔진·공유 규격은 그대로 유지한다. 기존 링크는 기존 결과를 읽는다. 새 홈·심리 허브·사용법 목록에서는 새 시리즈를 안내한다.
- 예전 관리자 게시본/서버 목록의 다섯 기존 항목을 새 항목으로 변환한다. 순서와 숨김 상태는 유지한다. MBTI·자리 선택은 독립 목록에서 제거한다. 신구 항목이 모두 게시돼 있으면 명시적인 새 항목을 우선해 중복을 막는다.
- 정식 MBTI, 심리 진단, 상대의 속마음 추측, 궁합 점수, 근거 없는 순위나 확률을 제공하지 않는다. 카드 해석은 창작 대화 놀이임을 표시한다.
- `main` 푸시가 기존 GitHub Pages 배포 경로다. DB 변경/새 서버 비밀키 없이 동작한다.

## 공유와 보관의 실제 동작

- 새 링크는 각 새 주소에 `#c=`(초대), `#r=`(답장 결과)와 v1 payload를 사용한다. 이름 12자, ID/시드, 에피소드, 선택 수와 범위를 검증한다.
- 초대 받은 사람에게는 자기 답과 예상 확정 전 상대 결과를 표시하지 않는다. URL 인코딩은 암호화나 부정행위 방지가 아니다. 링크를 가진 사람은 이름과 선택을 읽거나 바꿀 수 있는 가벼운 대화 게임이다.
- 자동 완료 알림 대신 **친구가 결과 링크를 답장**해야 발신자에게 전달된다. 타로의 행동 제안은 각자 실제로 선택한 값만 반영한다. 새 선택은 새 결과 링크를 보내야 다른 기기에도 전달된다. 오래된 링크는 당시 결과이며, 동일한 두 참여자의 최신 로컬 선택만 보완한다.
- 자기 기기에서 만든 초대/답장을 알아보고 관점을 정한다. 다른 기기에서 타로 행동이나 화해 문장을 고를 때는 본인이 어느 쪽인지 직접 선택한다. 계정 인증에 기반한 신원 확인 기능은 없다.
- 타로는 각자 선택 1회, 둘 다 같은 행동을 선택했을 때만 같은 제안이라고 표시한다. 함께 살기는 양쪽 모두 같은 규칙에 동의했을 때만 공동 동의로 표시한다. 건너뛴 질문은 유사도/중요도 비교에서 제외한다.
- `mind-series:*` 로컬 키에 자기/상대 답과 보관함을 저장한다. 타로/행운 보관함 지우기 및 브라우저 사이트 데이터 삭제가 가능하다. 차단된 저장소와 클립보드에서도 결과 링크 수동 복사를 제공한다. 수신한 행운 카드는 자신의 오늘 카드와 분리한다.
- 새 시리즈 공유 카드는 `assets/share-cards/{slug}.png` 800×480. 카카오 공유는 기존 공통 SDK를 이용한다. QA는 실제 사람에게 메시지를 보내지 않고 공유 payload를 확인한다.

## 측정

기존 서버 허용 이벤트를 사용하므로 통계 migration은 필요하지 않다. 이름·답·문장은 통계로 보내지 않는다.

- `game_started`, `link_made`, `invite_opened`, `responded`: 시작/초대 생성/초대 열기/수신자 완료. 에피소드는 method로 구분한다.
- `invite_shared` / `result_shared`: 카톡 창 호출 또는 복사 버튼 시도. 전달 완료나 상대의 읽음을 뜻하지 않는다.
- `result_opened` + `sender_read`: 같은 브라우저의 작성자가 답장 링크를 열었거나 본인 관점을 선택한 경우. 다른 기기를 자동 식별하지 않는다.
- `replay`: 다른 에피소드 시작으로 돌아가기.
- `game_completed` + `action_chosen`, `daily_draw`, `fortune_tried`, `fortune_later`: 타로 행동 선택/오늘 카드/선택적 반응. 기존 이벤트의 method이므로 기본 완료 합계와 세부 행동은 구분해서 분석해야 한다.
- `result_shared` + `message_copied`: 편집한 화해·타로 문장 복사 성공. 문자 내용은 보내지 않는다.
