# 톡톡 배틀

카톡 링크로 각자 휴대폰에서 겨루는 20초 초록/빨강 탭 게임. 크림·코랄 UI,
민트/코랄 선수 표시, 자체 게임방법, 준비·카운트다운·실시간에 가까운 점수 비교·결과·재대결.
혼자놀기에 노출하지 않는다. 알까기는 이 작업에서 수정하지 않았다.

## 실행과 배포 상태

로컬 구현/검토를 완료했고 사용자가 커밋·푸시·웹 배포를 요청했다(2026-09-14).
**운영 SQL은 사용자 실행 대기 중이다.** 웹 파일은 main 푸시로 GitHub Pages에 배포한다.
`supabase/migrations/20260914_tapbattle_rooms.sql`까지 운영 서버에 적용해야 초대 대결이 활성화된다.
기존 오목·알까기 SQL에는 변경이 없다. SQL은 재실행 가능하다.

`node scripts/tapbattle-preview.cjs` → http://127.0.0.1:4190/t/tapbattle/?player=0

이 서버는 실제 migration을 PGlite에서 실행하며 운영 DB에 연결하지 않는다.
호스트가 방을 만든 후 다른 탭에서 `?player=1#room=방코드`를 열면 친구가 된다.
테스트 참가자는 탭별 sessionStorage로 구분하며 실제 Supabase 인증을 대체하는 코드는
미리보기 서버가 HTML 응답에만 주입한다. 배포용 HTML/JS에 테스트 인증은 없다.
로컬에서는 실제 카톡 공유를 막고 미리보기 안내를 표시한다.

## 규칙과 동기화

- 둘 다 준비하면 서버가 4초 후의 공통 시작 시간을 지정한다. 준비 취소는 시작 확정 전만 가능.
- 20초, 초록 +1 / 빨강 −3. 음수 점수를 허용하고 동점은 무승부.
- 양쪽은 같은 seed로 같은 가변 길이 신호를 재현한다. 마지막 5초 안내는 표시만 바뀐다.
- 브라우저는 왕복 시간이 가장 짧은 응답으로 서버 시계를 추정하고, 경기 중에는 기준을 고정한다.
- 실제 입력은 pointerdown 또는 스페이스/엔터로 즉시 반영한다. 키를 계속 누르는 반복 입력은 제외.
- 연속 성공은 부가 기록이며 승패는 점수로 결정한다.
- 약 650ms + 요청 왕복 시간마다 RPC로 이벤트를 보내고 상대 점수를 받는다.
  WebSocket이나 틱톡 서비스 연동은 아니다. 연결에 따른 상대 점수 지연을 화면에 알린다.
- 서버가 양측 점수를 재계산한다. 35ms 미만 간격, 미래 150ms 초과,
  5초 초과 지연, 범위 밖 입력, 변경된 과거 이력은 거부한다. 최대 572회.
- 전체 append-only 입력 이력을 재전송해 재시도/역순 도착에 점수가 중복되지 않는다.
  재접속은 서버에 저장된 내 이력과 탭에 남은 미전송 이력을 병합한다.
- 최근 응답이 2.6초 넘게 없거나 오프라인/백그라운드이면 입력을 잠근다. 경기는 계속 흐른다.
  4.4초가 지나 미전송 상태인 터치는 다음 전송에서 제외해 서버 허용 시간을 넘기지 않는다.
- 종료 후 3초 전달 유예 뒤 기록을 확정한다. 상대가 돌아오지 않아도 조회 시 종료된다.
- 재대결은 둘의 동의 후 준비방으로 복귀한다. 다시 양측 준비가 필요하다.
- 양보하면 즉시 상대 승리. 방은 24시간 유효하며 세 번째 참가자/관전은 거부한다.

## 보안과 한계

공용 `GroupRoomService.ensureSession()`의 Supabase 익명 인증과 카카오 공유 모듈을 재사용한다.
32자리 무작위 방 코드만 초대 URL에 포함하며 인증 토큰, UID, 요청 식별자를 노출하지 않는다.
테이블은 RLS 및 직접 접근 차단, 보조 함수는 실행 권한 차단,
공개 RPC는 인증/참가자/라운드 확인과 방 행 잠금을 사용한다.
상대의 원시 입력 이력은 노출하지 않고 집계 결과만 반환한다.

터치 시간은 클라이언트 제출값이라 변조된 클라이언트/자동 입력을 완전히 막지 못한다.
서버 검증은 중복·범위·속도·상태 오류 방지가 목적이다. 기기/네트워크 지연 차이도 남는다.
따라서 친구 간 캐주얼 게임으로 설계했으며 정밀 측정/상금 대회용 신뢰 수준은 아니다.
방 참가자가 화면을 숨겨도 이미 눌러둔 준비는 자동 취소되지 않는다. 재접속 시 남은 경기로 복귀한다.

## 검증

- `node test/tapbattle.cjs`: JS/SQL 신호·점수 일치, 권한, 준비/취소, 시간 검증,
  동시/중복 전송, 기록 비공개, 종료 유예, 양보, 재대결, 만료, migration 재실행.
- `node test/tapbattle-invite.cjs`: 명시적 공유, 링크/클립보드 대체 동작, 중복 생성 방지.
- `node scripts/check-tapbattle.cjs`: 실제 Edge 두 참가자, 터치/키보드, 오입력 감점,
  점수 전달, 새로고침, 오프라인 복귀, 자연 종료, 재대결, 양보,
  320/390/768/1024px 레이아웃, 게임방법, 둘이놀기 메뉴.
- 화면 확인 결과는 `output/tapbattle/`에 생성한다.

## 알까기 별도 피드백 (미적용)

사용자는 선공 유리함을 지적했다. 현재 동일 AI 양쪽 시뮬레이션 1회에서
5:4 → 4:4 → … → 1:0 선공 승리가 재현됐다. 이것은 전 배치/전략에 대한 증명은 아니다.
제안은 방향 직접 고정 + 오르내리는 힘 게이지. 움직이는 방향 화살표는 기본 모드에서 제외.
사용자의 배치 변경 제안에는 앞줄 3개·뒷줄 2개의 엇갈린 배치를 권했다.
양쪽은 같은 배치를 180도 회전해 조건을 맞추되 선후공 교차 검증이 필요하다.
첫 타격 힘 제한, 엇갈린 대칭 배치, 재대결 선공 교대는 별도 균형 실험 후보다.
