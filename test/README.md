# 기록 대결 골든 테스트

`assets/duel-engine.js` 나 `t/{ten,react,num25,mole,tap}/index.html` 처럼 기록 대결 공통 부분을 바꾸면 `npm test` 로 골든 비교부터 한다 — 화면 문구·도전장 링크(`#c=` `#r=`)·전적·카톡 카드가 이전과 바이트 단위로 같은지 `test/golden.json` 과 맞춰 본다.

차이가 나면 링크 형식이나 문구가 바뀐 것이니, 의도한 변경이 맞을 때만 `npm run test:update` 로 스냅샷을 갱신하고 무엇이 바뀌었는지 커밋 메시지에 남긴다 (`npm test` 는 스냅샷을 절대 자동으로 고치지 않는다).

새 기록 대결 게임을 만들면 `test/scenarios.js` 의 `GAMES` 와 `REC` 에 한 줄씩 더해 시나리오에 포함시키는 것을 기본으로 한다. 화면 구조가 다른 게임(가위바위보 등)은 `test/rps.js` 처럼 파일을 따로 두고 `snapshot()` 에서 불러 쓴다.

## 쓰는 법

```bash
npm install     # 처음 한 번 (jsdom)
npm test        # 골든 비교
npm run test:update   # 의도한 변경일 때만 스냅샷 갱신
```

## 시나리오

게임마다 아래를 찍는다. `test/scenarios.js` 참고.

| # | 시나리오 | 보는 것 |
|---|---|---|
| 1 | 첫 진입 | 해시 없이 들어왔을 때 플레이 화면 |
| 2 | 조사 헬퍼 | `subj`·`topic`·`objp`·`subjTail`·`who` 출력 |
| 3 | 도전장 링크 | `#c=` 바이트, 링크 상자, 카톡 도전장 카드 (첫 판·2판째) |
| 4 | 응답 → 결과 | 도전장 열기, 응답, 결과 화면 전체, `#r=` 링크, 카톡 결과 카드 |
| 5 | 이름 없는 도전장 | 이름이 비었을 때 `상대가 도전했다` |
| 6 | 결과 링크 보기 | 도전한 쪽이 결과 링크로 들어왔을 때 |
| 7 | 전적 | `tallyOf`·`histRows` (id 기준 / 옛 이름 기준) |
| 8 | 봉인·인코딩 | `lockNum`/`unlockNum`, `b64e`/`b64d` 왕복 |
| 9 | 내기 걸기 | 낱말·문장·GA, 내기 링크 바이트, 열기 한 줄, 결과 승/패/무, 재도전 승계, 직접 입력 |
| 10 | 옛 링크 | 플레이어 id 가 없던 시절 결과 링크도 열리는지 |

가위바위보(`test/rps.js`)는 화면이 달라 따로 찍는다 — 도전장 링크(이름 있음/없음·내기·직접 입력)·카톡 카드·열기·응답·결과 양쪽 시점·비긴 판 이어가기·복수전 승계·무승부·옛 형식 링크·깨진 해시.

`Math.random` 과 `performance.now` 는 고정해 두어 같은 코드면 항상 같은 스냅샷이 나온다.
